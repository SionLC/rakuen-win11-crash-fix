# 《乐园》汉化版兼容启动修正 v1.01

修复指定版本 `rakuen_cn_160916.exe` 的启动闪退及高 DPI 环境下的字形异常。补丁仅作用于运行内存，不覆盖原游戏程序、资源包或存档。

## 使用方法

1. 关闭已有游戏窗口，首次使用建议备份 `SAVE`。
2. 将 **`rakuen_compat.exe` 复制到游戏根目录**，与原来的 `rakuen_cn_160916.exe` 放在一起，不要覆盖或替换原 EXE。
3. 双击 `rakuen_compat.exe`，以后也通过它启动游戏。**不需要使用 Locale Emulator 转区运行。**

如果补丁放在其他目录，双击后会弹出选择框，选择完整游戏目录中的 `rakuen_cn_160916.exe` 即可。

```text
游戏根目录/
├── rakuen_compat.exe        ← 从这里启动
├── rakuen_cn_160916.exe     ← 保留原文件
├── ……其他游戏文件
└── SAVE/
```

## 适用版本与注意事项

- 适用于 Windows x64，需要 .NET Framework 4 系列运行时；已在 Windows 11 简体中文系统区域环境验证启动、场景及短段对白，未进行全流程通关测试。
- 本补丁不含游戏或汉化资源，需准备对应版本的完整汉化游戏。非中文系统区域环境尚未验证。
- 不需要 Python、额外字体或源码，通常不需要管理员权限，也不必叠加 XP 兼容模式或转区工具。
- 启用高 DPI 感知后，窗口可能比系统自动放大时小，这是正常的显示差异。
- 游戏正常运行、保存或退出时仍可能写入存档；补丁不会自动备份存档。
- 修复随游戏退出而消失，下次仍需通过补丁启动。新版不自动生成日志文件，启动错误会直接弹窗提示。
- 启动器校验原程序版本及目标指令；不匹配时会拒绝修复，请勿绕过校验。

目标原程序：`rakuen_cn_160916.exe`，4,738,939 字节，SHA-256：

```text
2715DDD3435D19E980CA09B9EEF54A0C7B0879C715AFD0D4820CE90BD49ED0DA
```

## 修复原理

**空字形处理：** 原程序在 `GetGlyphOutline` 返回 `0` 的分支中，没有可靠初始化供后续复制使用的 `GLYPHMETRICS`，导致非法内存访问。补丁在该分支将字形度量的 20 字节清零，再按原调用约定返回，保留正常字形的原有绘制流程。

**高 DPI 兼容：** 字形 Hook 曾发现，旧引擎按 23 像素准备缓冲区，接口返回的某些字形却达到 36 像素高。启动器为本次运行设置 `HIGHDPIAWARE`，避开已验证环境中的 DPI 虚拟化尺寸不一致。此设置不修改全局缩放或注册表。

启动器先校验原 EXE，再通过 Windows 调试 API 等待目标函数就绪，在游戏进程内存中写入修复并回读验证，最后脱离调试器，让游戏独立运行。不会替换游戏字体，也不会改写原 EXE。

普通玩家只需要补丁 EXE。开发者可在具备 .NET Framework 4 系列 x64 C# 编译器的 Windows 上运行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\源码\编译.ps1
```

脚本直接生成或覆盖本说明旁边的 `rakuen_compat.exe`，不创建其他发布目录。图标已嵌入 EXE，使用时不需要另带 ICO 文件。
